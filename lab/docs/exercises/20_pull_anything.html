Integration stops being a project.
It's a FROM clause.

ClickHouse's table functions make URLs, files, S3 buckets, and other databases queryable as if they were local tables — schema inferred, aggregation pushed down. Master this and "build a connector" stops appearing on your roadmap.

A · A remote file is a table

One FROM clause, no ingestion

SELECT town, district, count() AS sales, round(avg(price)) AS avg_price
FROM url(
    'https://datasets-documentation.s3.eu-west-3.amazonaws.com/uk-house-prices/parquet/house_prices_2022.parquet',
    Parquet)
GROUP BY town, district
ORDER BY sales DESC
LIMIT 10;

No ingestion happened. ClickHouse streamed a remote Parquet file, pushed the GROUP BY down, and answered. Schema was inferred. Inspect what it inferred: 

DESCRIBE url('https://datasets-documentation.s3.eu-west-3.amazonaws.com/uk-house-prices/parquet/house_prices_2022.parquet', Parquet);
B · Ingestion = INSERT SELECT

The universal bulk-import recipe

CREATE TABLE lab.house_prices
ENGINE = MergeTree ORDER BY (town, date)
EMPTY AS SELECT * FROM url('https://.../house_prices_2022.parquet', Parquet);

INSERT INTO lab.house_prices
SELECT * FROM url('https://.../house_prices_2022.parquet', Parquet);

Two statements: EMPTY AS SELECT clones the schema, then INSERT SELECT hauls the rows in. Works for any source the table function supports.

C · The table function family

Same pattern, every system

FunctionFor
s3('s3://bucket/path/*.parquet', ...)Object storage, glob patterns
file('/var/lib/clickhouse/user_files/x.csv')Local files
postgresql('host:5432','db','table','u','p')Live Postgres (see exercise 22)
mysql(...), mongodb(...), redis(...)Other databases
remote('other-ch:9000', db.table)Another ClickHouse cluster
url('https://api...', JSONEachRow)Any HTTP API that emits rows
hdfs(...), azureBlobStorage(...), iceberg(...), deltaLake(...)Data-lake formats

Each also exists as a persistent table engine — same args, but you CREATE TABLE … ENGINE = S3(...) once instead of inlining the function everywhere.

D · Export

Same thing, backwards

SELECT * FROM lab.events_1m LIMIT 100
INTO OUTFILE '/var/lib/clickhouse/user_files/rollup.parquet' FORMAT Parquet;

ClickHouse speaks ~70 formats. INSERT INTO FUNCTION s3(...) writes straight to a bucket — CH as the ETL engine, not just a destination.

E · clickhouse-local

The engine without the server

# Full SQL on local files, zero setup:
docker exec clickhouse clickhouse-local -q "
  SELECT count() FROM file('/var/lib/clickhouse/user_files/rollup.parquet', Parquet)"

Replaces half of pandas/awk for data wrangling. Pipe anything in, SQL it, pipe anything out. The most underrated integration tool ClickHouse ships.

F · Gotchas

What experts know

Trap Schema inference happens once, at first read. If the file changes shape between reads, queries silently truncate or misparse. Pin the schema with explicit column lists in DESCRIBE output, or use the persistent table engine form.
Pattern Filter pushdown works for some sources, not all. Parquet/S3 = yes (very efficient); url/JSONEachRow = no (entire stream pulled). Check EXPLAIN if performance surprises you.
Pattern S3 glob patterns enable scatter-gather queries. s3('s3://bucket/year=*/month=*/data.parquet') reads many files in parallel — ClickHouse becomes a query engine over a data lake without Spark.
